## 📌 Executive Summary & Architecture

Highway maintenance operations are divided into **four distinct operational lanes**:
1. **L01: Highway Left** (Main highway high-speed outer/left lane & median shoulder)
2. **L02: Highway Right** (Main highway high-speed inner/right lane & safety barrier)
3. **L03: Service Road Left** (Parallel service arterial road left boundary & drainage trench)
4. **L04: Service Road Right** (Parallel service arterial road right boundary & curb walkway)

The system features dynamic cryptographic QR attendance verification, Haversine GPS geofencing, photographic before/after cleaning evidence logging, strict role-based access control (RBAC), and unified dispatch scheduling.

```
+-----------------------------------------------------------------------------------+
|                        SMART HIGHWAY CLEANING ECOSYSTEM                           |
+-----------------------------------------------------------------------------------+
|  1. Dispatch         |  2. Execution        |  3. Evidence        |  4. Verification  |
|  Supervisor assigns  |  Worker starts       |  Worker captures    |  Worker travels   |
|  worker to specific  |  cleaning on         |  before/after       |  to hub & scans   |
|  lane & shift.       |  assigned corridor.  |  photographs.       |  dynamic QR.      |
+-----------------------------------------------------------------------------------+
```

## 🚀 Key Modules & Capabilities

### 1. Dedicated Four-Lane Management
- Configurable highway sections (corridor code, region, start km, end km).
- Real-time lane operational status: `IDLE`, `ASSIGNED`, `IN_PROGRESS`, `COMPLETED`.
- Multi-lane dispatch table with lane filtering, shift scheduling, and reassignment.

### 2. Cryptographic Dynamic QR Attendance Engine
- Dynamic, short-lived QR codes generated by authorized hub operators (30–60 second validity).
- Cryptographically signed with **HMAC-SHA256** using hub nonces and server-side timestamps.
- **Strict Anti-Replay Protection**: Single-use tokens tracked in database (`HubQrToken.isConsumed`); consumed tokens are immediately rejected.
- **Hub Mismatch Protection**: Cross-hub scan attempts are automatically blocked.
- **Work Completion Pre-requisite**: Scanning a QR code does *not* automatically complete attendance. The system enforces that the assigned cleaning task is `COMPLETED` or `VERIFIED` with uploaded photographic evidence before attendance can be granted.

### 3. Geofencing & Nearest Hub Detection
- Real-time GPS coordinate telemetry with Haversine distance calculations.
- Hub geofence perimeter validation (default: 500m radius).
- Supervisory exception workflow for field workers in GPS-denied environments.

### 4. Photographic Evidence & Incident Reporting
- Direct photo upload (before-cleaning, after-cleaning, obstruction/incident photos).
- GPS location tagged to evidence records.
- Incident severity logging (`LOW`, `MEDIUM`, `HIGH`, `CRITICAL`).

### 5. Fixed Hierarchical Role-Based Access Control (RBAC)
- **Super Administrator (Level 5)**: Complete system control, highway corridor creation, audit trails, and policy configuration.
- **Operations Administrator (Level 4)**: Workforce registration, shifts, lane dispatching, and operational monitoring.
- **Supervisor (Level 3)**: Team roster monitoring, work verification, exception justification, and task assignment.
- **Hub Operator (Level 2)**: Dynamic QR generation, check-in stream monitoring, and terminal operations.
- **Field Worker (Level 1)**: Mobile interface, assigned tasks, photographic evidence upload, and QR scanning.
- *Strict hierarchy enforcement: Lower tiers cannot access upper-tier administrative portals.*

## 🗄️ Database Architecture

Supports both **Local Offline SQLite** and **Free Web-Based Cloud PostgreSQL** (Neon Serverless Postgres / Supabase).

```bash
# Switch to Free Cloud PostgreSQL (Neon / Supabase):
npm run db:switch:postgres
npm run db:push
npm run db:seed

# Switch back to Local SQLite:
npm run db:switch:sqlite
```

## 🛠️ Quick Start & Installation

### Prerequisites
- Node.js (v18 or higher)
- npm or pnpm

### 1. Clone & Install
```bash
git clone https://github.com/Dhee0104-ux/cleanup.git
cd cleanup
npm install
```

### 2. Configure Environment
```bash
cp .env.example .env
```

### 3. Initialize Database & Seed
```bash
npm run db:push
npm run db:seed
```

### 4. Build Frontend
```bash
npm run build
```

### 5. Launch Server
```bash
npm start
```
The server will be available at `http://localhost:4001`.

## 🔐 Security Features

- **Sensitive Data Sanitization**: Recursive response interceptor scrubs `passwordHash`, `secret`, and `jwtSecret`.
- **HTTP Security Headers**: HSTS, CSP, X-Frame-Options (`DENY`), X-Content-Type-Options (`nosniff`).
- **Rate Limiting**: Configured per endpoint to prevent brute-force attacks.
- **Audit Logging**: Immutable database logs for all authentication, dispatch, QR verification, and exception approvals.
